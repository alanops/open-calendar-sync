# Self-hosting

Run one installation for one person's calendar accounts. The MIT software is free; hosting and domain costs are yours. The server must remain running for automatic sync. Use Linux, macOS, WSL or the supplied Linux container.

## Docker Compose

Create `.env` with the setup command in the README, or fill `.env.example` with newly generated values. Never use placeholder access keys or encryption keys.

```bash
docker compose up -d --build
```

The default setup binds only to `127.0.0.1:8000`. Open `http://localhost:8000`; credentials stay in `.env`, and SQLite persists in the named `calendar-data` volume. The container runs as an unprivileged user, with dropped capabilities and a read-only root filesystem.

## HTTPS on your domain

Use a separate subdomain to keep the app independent of an existing WordPress or other website. For example, `calendar.alanops.com` is a possible deployment name; this repository does **not** configure or claim that hostname.

1. Point a subdomain's DNS A/AAAA records at your server.
2. Set `BASE_URL=https://calendar.your-domain.example` in `.env` and register the corresponding OAuth callback URLs.
3. Run the app with Compose, then install Caddy or use your existing reverse proxy. The example `deploy/Caddyfile` forwards to loopback port 8000 and obtains HTTPS certificates. Replace its placeholder hostname.
4. Open only the proxy's HTTPS/HTTP ports publicly. Keep port 8000 on loopback. Avoid enabling query-string/access logs on OAuth callback endpoints.
5. Open the dashboard, use your private access key, connect accounts and test disposable events before enabling regular sync.

Do not install Caddy over an existing web server's ports without integrating with that server's routing. On an existing alanops.com host, add a dedicated virtual host to the current proxy instead if necessary.

## Configuration

| Variable | Purpose |
| --- | --- |
| `BASE_URL` | Exact externally reachable HTTP(S) origin, no trailing slash or path. Non-loopback origins require HTTPS. |
| `ADMIN_TOKEN` | Random dashboard access key, at least 32 characters. Generated by `python -m calendar_sync.setup`. |
| `ENCRYPTION_KEY` | Fernet key, generated by setup. Preserve it with database backups. |
| `DATA_DIR` | SQLite and worker lock directory; `data` by default. Compose overrides this to `/app/data`. |
| `SYNC_INTERVAL_SECONDS` | Poll interval, 300 by default; 60–86400 accepted. |
| `SYNC_DAYS_AHEAD` | Future sync window, 90 by default; 1–365 accepted. Previous seven days are also included. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Your Google OAuth web-client credentials. |
| `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET` | Your Microsoft Entra web-app credentials. |
| `MICROSOFT_TENANT` | `common`, `organizations`, or your directory ID, matching the registration. |

## Operations

- `/healthz` reports that the application is responding. It does not imply calendars are connected or the last sync succeeded; check the authenticated activity log for that.
- Run **one Uvicorn process**. Do not use `--workers`, multiple replicas, shared NFS storage or multiple installations on the same calendars.
- The app persists pause state. Restarting an active installation resumes automatic syncing.
- A failed source read stops the cycle before writes. A later write failure can leave earlier copies applied; the next successful cycle reconciles them. Cleanup only begins after desired writes succeed.
- Pause stops future sync cycles once any in-flight cycle finishes. Existing Busy copies remain until cleanup or a later successful sync.
- Before uninstalling, use **Disconnect & clean up** while all accounts remain authorized. This removes this installation's copies before deleting credentials. Then revoke the OAuth grants in the provider account settings.
- Back up SQLite consistently, using SQLite's backup API or stopping the service first. Keep the matching `.env` encryption key protected. A database restored from an old backup can have incomplete copy tracking; do not resume blindly.
- Rotating `ADMIN_TOKEN` does not invalidate existing sessions immediately. For immediate logout, stop the app and remove the `sessions` rows from SQLite before restarting. Sessions expire after 12 hours.
- `ENCRYPTION_KEY` is not automatically rotated. Changing it without re-encrypting tokens makes existing account access unreadable.

## Public SaaS hosting

This version deliberately has no registration, tenant isolation or per-user billing. A public free service would need per-user authentication, separated credentials and jobs, quotas, abuse controls, OAuth verification, deletion/export flows, a privacy policy and an operational support model. Host a separate private instance for each owner rather than opening this instance to unrelated users.
